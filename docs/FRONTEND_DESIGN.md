# フロントエンド詳細設計

[DESIGN.md](DESIGN.md) のフロントエンド部分の詳細設計。[BACKEND_DESIGN.md](BACKEND_DESIGN.md) のAPI・データモデルと1対1で対応する。

## 開発基盤

詳しい規約は [CLAUDE.md](../CLAUDE.md)。

```bash
./dev.sh          # バックエンド(8000)+フロント(5173)を起動
./dev.sh check    # pytest + typecheck + lint + vitest + build を一括実行
./dev.sh e2e      # Playwright(GPUもLLMも不要)

cd frontend && npm run gen:api   # APIを変えたら型を再生成
```

- **API型は自動生成**: FastAPIのOpenAPI → `src/api/schema.d.ts`。
  サーバー未起動でもFastAPIアプリから直接生成できる
- **E2Eは実LLM/GPU不要**: `backend/e2e_server.py` がFakeLLM+一時DB+シードAPIで起動するため、
  「文字起こし→指示語提案→承認」まで決定的にテストできる
- TypeScriptは5.9系に固定(6系はopenapi-typescriptと非互換)

## 技術スタック

| 項目 | 採用 | 理由 |
|---|---|---|
| フレームワーク | React 19 + TypeScript + Vite | 部品の豊富さ・Tauri移行時もそのまま使える |
| UI部品 | Tailwind CSS + 自前の薄い部品(`components/ui.tsx`) | 部品ライブラリを足すほどの画面数ではなかった。shadcn/uiは採用していない |
| サーバー状態 | TanStack Query | ジョブ・セグメント等のAPI状態のキャッシュ・再取得を宣言的に管理 |
| UI状態 | Zustand | 再生位置・選択セグメント・タイムラインズーム等の高頻度更新をReact外で保持 |
| 動画再生 | HTML5 `<video>` | ブラウザネイティブ。mov/mp4はそのまま、非対応コーデックはバックエンドでプロキシ変換 |
| タイムライン | 自前(`clips/ClipTimeline.tsx`) | クリップ範囲の調整に波形は要らなかった。wavesurfer.jsは採用していない |
| 長リスト | TanStack Virtual | セグメント1,400行超(実測: aiイベント本編)でも滑らかに表示 |
| 進捗受信 | SSE (EventSource) | バックエンドの `GET /api/jobs/{id}/events` に対応 |

## 画面構成

### 1. プロジェクト一覧(ホーム)
- プロジェクト作成・動画ファイル登録(パス指定 or ドラッグ&ドロップ)
- 各メディアの処理状態バッジ(未処理/文字起こし中/完了)と進捗バー

### 2. 編集画面(メイン)

```
┌─────────────────────────────┬──────────────────┐
│  動画プレビュー                │  右パネル(タブ切替) │
│  + 字幕オーバーレイ(CSS)       │  ├ トランスクリプト   │
│  + 再生コントロール             │  ├ 置換レビュー      │
│                              │  ├ 切り抜き候補      │
│                              │  └ 設定            │
├─────────────────────────────┴──────────────────┤
│  タイムライン                                      │
│  [波形] [セグメント帯(話者色)] [切り抜き候補帯]        │
│  ズーム・シーク・範囲ドラッグ                         │
└────────────────────────────────────────────────┘
```

#### トランスクリプトタブ
- セグメントを話者色付きで一覧(仮想スクロール)。クリックで動画シーク、再生位置に追従してハイライト
- インライン編集(テキスト・話者変更)→ `PATCH /api/segments/{id}`
- 相槌セグメントはグレー表示(設定により非表示/復活切替)。フィラー除去語は取り消し線表示、クリックで復活
- 指示語置換済みの箇所は下線表示。ホバーで原文をツールチップ表示
- 選択字幕モード時: 各行に字幕採用バッジ(採用/不採用+根拠タグ)。クリックで切替(→ user_show/user_hide、feedbackに記録)。字幕プレビューは採用分のみ表示

#### 置換レビュータブ(Human-in-the-loop の中心)
- `GET /api/media/{id}/edits` を diff 形式で表示(置換前→置換後、行ジャンプ付き)。
  「レビュー待ち(review)」と「適用済み(auto)」をセクション分け、レビュー待ち件数をタブにバッジ表示
- 各提案に **承認 / 修正して承認 / 却下** の3ボタン。却下時は理由を任意入力(→ feedbackとして次回実行のfew-shotに使われる)
- キーボード操作で高速レビュー(j/k移動・a承認・x却下)。1,000件規模でも数分で捌ける操作性を優先
- ヘッダに「未解決のみ再実行」「選択範囲を再実行」ボタン。再実行時に追加指示を1行入力できる
  (入力した指示は「今後も使う」チェックでプロジェクトのカスタム指示に昇格)
- 適用済みは1件ずつ取り消し可 → `POST /api/edits/{id}/revert`

#### 質問キュー(LLMからの質問に答える)
- ヘッダに未回答件数バッジ。カード形式で1問ずつ表示:
  「『反動体』(12回出現)は『半導体』の誤認識と思われます。正式表記は?」
  - 推定候補をボタンで提示(ワンタップ回答)+ 自由入力欄。出現箇所へのジャンプリンク付き
- 回答すると: 用語集に自動登録 → 全出現箇所を一括修正 → 修正件数をトースト表示
- 「後で」「この質問を却下」も可能。未回答でも他の作業はブロックされない

#### 対話アシスト(セグメント選択時)
- トランスクリプトでセグメントを選択 → 「AIに指示」ボタンでミニチャットを開く
- 例:「この『それ』は文字起こしアプリのこと」→ `POST /api/segments/{id}/assist` → 編集提案カードが返り、承認で適用
- 会話の結論がルール化できる場合、「カスタム指示に追加しますか?」の昇格提案を表示

#### 切り抜き候補タブ(Phase 2)
- 目標尺セレクタ(Shorts 60秒 / TikTok 30秒 / カスタム)→ 候補生成
- 候補カード(スコア順): サムネイル・自動タイトル案・長さ・**スコア根拠タグ**(「完結した話題」「笑いあり」「フック強い」)
- カードの採用ボタンでクリップ化 → クリップ編集モードへ。不採用はスワイプで除外(理由はfeedbackへ)

#### クリップ編集モード(候補採用後の再調整画面)
1本のクリップに集中する専用ビュー。タイムラインはクリップ範囲だけを拡大表示:

- **トリム**: 両端ドラッグ。既定でセグメント境界・無音・話者交替点に**スナップ**(磁石アイコンで解除可)。
  文の途中で切れる位置にはドロップ時に警告表示
- **中抜き(ジェットカット)**: `POST /clips/{id}/jetcut` の提案区間をタイムライン上に斜線帯で表示。
  クリックでON/OFF。プレビュー再生は中抜きを反映してスキップ再生。現在尺/目標尺のカウンタを常時表示
- **指示語の自己完結化**: 「クリップ内で通じない指示語」を検出したらバナーで通知 →
  ワンクリックで `POST /clips/{id}/resolve` → 置換レビューと同じUIで承認
- **フックテキスト**: 冒頭テロップのLLM3案をチップ表示、選択・編集。冒頭3秒プレビューボタン
  (最初の画+字幕がフックになっているかを即確認)
- **レイアウト**: 横型/縦型(顔追従)/縦型上下分割の切替とプレビュー
- 完了 → 書き出しキューへ

#### 書き出しキュー
- キューに積んだクリップを一覧(テンプレート・尺・状態)。テンプレート一括適用
- `POST /api/export/batch` で連続書き出し、SSEで各クリップの進捗表示
- 書き出しダイアログ: 解像度・字幕焼き込み有無・出力先・ファイル名パターン(連番/タイトル)

#### 設定タブ
バックエンドの `core/config.py` と1対1で対応するフォーム(`settings/SettingsFields.tsx`)。
**Settings に無い項目はUIにも出さない。** 出したままにすると「切ったのに効かない」になる
(実際に4項目がそうなっていて、2026-08-09に消した)。

- ASR: エンジン(自動/faster-whisper/whisper.cpp/公式Whisper)・モデル・言語・ビーム幅・VAD
- 話者分離: 有効/無効・エンジン・人数・話者名(男女自動判定の表示名)
- 相槌: 相槌とみなす最大の長さ(除外は常に行う)
- フィラー排除: 無効/弱/強
- 指示語置換: 積極性(強/中/弱)・表現形式(注釈/置換/補完)・適用モード
- 字幕: 採用率・フォント・サイズ・色・背景・表示位置・上下微調整・話者別色・1行最大文字数
- 向き変換: 中央クロップ/ぼかし余白/顔検出
- LLM: プロバイダ(Ollama/Gemini/Claude)とモデル。APIキーは `ApiKeysPanel` から登録する
- リソース: VRAM割当(0=無制限)

設定は3層(グローバル → プロジェクト → クリップ)。プロジェクトはグローバルとの
**差分だけ**を持つので、上書きしていない項目はグローバルの変更に自動で追従する。

同じフォームをプロジェクト設定パネルからも使う(`idPrefix` で testid を分ける)。

#### 設定タブのその他のパネル
- `EnvironmentPanel`: GPU・VRAM・エンコーダ・Ollamaのスキャン結果と推奨設定。
  「おすすめ設定を適用」はモデルだけを保存し、**エンジンは `auto` のままにする**
  (具体名で固定すると、同梱物が増えて推奨が変わっても追従しない)
- `SetupPanel`: 足りていないモデルの案内とその場での取得(進捗はSSE)
- `ApiKeysPanel`: Gemini / Claude のAPIキー登録。平文ファイル+0600で保存する
- `LicensePanel`: ライセンスキーの登録と状態
- `OpenSourcePanel`: 同梱物のライセンス表記(LGPLのFFmpegはここに出す義務がある)

### 3. 字幕プレビューの方式
- 編集中のプレビューは **CSSオーバーレイ**で近似(位置・フォント・色・背景・最大文字数での折返し・禁則はフロントで再現)
- 最終出力はバックエンドのASS焼き込み。「プレビュー=近似、書き出し=正」と明示し、書き出し前に1クリップだけ試し書き出しできる「プレビュー書き出し」ボタンを設ける

│   │   ├── edits/      ReviewTab

│   │   ├── clips/      ClipsTab, ClipTimeline
│   │   ├── export/     ExportTab
│   │   ├── project/    CreateProjectForm, ProjectSettingsPanel
│   │   ├── settings/   SettingsForm, SettingsFields, SaveBar,
│   │   │               EnvironmentPanel, SetupPanel, ApiKeysPanel,

  `schema.d.ts` は自動生成物なので手で編集しない

## 状態管理の設計

- **サーバー状態**(TanStack Query): segments / edits / clips / jobs。SSE進捗イベント受信時に該当queryを無効化して再取得
- **UI状態**(Zustand): 再生位置(60fps更新のためReact re-render外で保持し、購読コンポーネントのみ更新)・選択セグメント・タイムラインズーム・タブ
- 再生位置とトランスクリプトの同期: `timeupdate` → ストア更新 → 二分探索で現在セグメント特定 → ハイライト&自動スクロール(手動スクロール中は追従を一時停止)

## 日本語特化のUI考慮

- 字幕折返し・禁則処理のロジックはフロントでも実装(`useSubtitleLayout`)し、プレビューと書き出しの見た目差を最小化。バックエンドと同一のテストケースを共有する
- フォントは Noto Sans JP / M PLUS 等の日本語Webフォントを同梱(オフライン動作のためローカル配信)
- セグメント検索は正規化(全half/角・かな/カナ)を吸収したあいまい検索

## 実装状況

Phase 1〜3はすべて実装済み(ホーム・編集画面・切り抜き・書き出し・Tauri配布)。
経緯とマイルストーン単位の受け入れ基準は [V1_PLAN.md](V1_PLAN.md) にある。

**採らなかったもの**(構想には挙げたが実装していない):
- 波形表示。クリップ範囲の調整に必要なかった
- 多言語UI。日本語の対談動画に特化しているため
- ショートカットキーは置換レビュー(a/x)だけに絞った

## 非機能

- すべてローカル配信(CDN不使用)でオフライン動作
- 75分動画(セグメント1,400行)で編集画面の初期表示2秒以内・スクロール60fpsを目標
- 破壊的操作(一括取り消し・書き出し上書き)は確認ダイアログ必須
